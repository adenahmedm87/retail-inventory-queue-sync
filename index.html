Reliability Behaviour

Duplicate scans: An attendee who is already pending or checked in cannot create a second badge print request.

Out-of-order callbacks: Every badge request has its own unique print job ID. Webhook confirmations are matched using that ID instead of arrival order.

Queue failure: If the RabbitMQ print request cannot be published, the pending check-in is rolled back so the attendee can safely try again.
